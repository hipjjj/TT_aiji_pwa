# 拳头份量参考

检索日期：2026-10-15。通过 `Review public hand portion references` 手动工作流抓取公开网页，不读取用户数据。

- [Precision Nutrition: Hand portion FAQ](https://www.precisionnutrition.com/hand-portion-faq)：网页表格明确列出 `1 fist (veggies) ~1 cup non-starchy vegetables`，并把蛋白质的掌心与碳水的捧手分开。该来源不是“所有食物一拳等于固定克数”的依据。
- [Diabetes UK: Portion sizes](https://www.diabetes.org.uk/living-with-diabetes/eating/portion-sizes)：网页举例拳头大小的带皮烤土豆、红薯约220g，说明不同食物/手势不能共用固定克重。应用未把此220g套用到水煮土豆。
- [USDA SR28 数据来源](food-data.md)：沿用项目已固定提交及SHA256校验的原始SQLite `weight` 表，从同一食品编号的 `amount, description, gm_weight` 提取杯重；半杯记录按比例换算一杯。生成文件 `src/nutrition/hand-portions.json` 保存原始数值、切法和编号，可运行原食物库生成脚本复现。

实现约定：将1拳≈1杯作为视觉体积的粗估起点，推广到有同种食品杯重的部分固体食物是**本应用的估算约定**，不是来源机构针对所有食物的推荐。不是个人拳头测量或克重标准。每一项生成克数和完整假设，用户可修改；熟菠菜180g/杯、生菠菜30g/杯，严格使用对应状态。油不自动计入水煮食物。没有杯重的食物不按统一密度填值；新增的AI预估子库见下方，仍无条目的食物可改填克数、选择食物或问AI。

已支持35项常见食品及其食物库别名，支持一拳、两拳、半拳、两个拳头等前后缀。仅使用杯重子库时，原句“米饭400g+炒牛肉两拳+萝卜叶半拳”只能确定米饭；下方AI扩展单独提供明确标注的菜品和营养参考，不把它们伪装成实测数据。

CDC页面抓取返回403、BHF旧地址404；二者未作为实现依据。

## AI预估扩展（2026-10-15）

在用户授权预估后，新增 `ai-hand-portions.json` 的62条AI预估，覆盖食材、果蔬、坚果及常见中餐；合计97项（原35项杯重参考优先，互不覆盖）。这些数值由AI助手预先给出，并非实时调用用户OpenAI服务，也不是测量、文献事实或经校准的个人拳头尺寸。每项保留默认克数、粗略上下范围、食材状态/切法/松紧假设和低置信度标记；上下范围是主观参考，不是统计置信区间。液体、调味油、部分汤粥等不强行添加拳头换算。

另外新增两条明确标为AI参考的食物：炒牛肉采用熟瘦牛肉200g＋油10g的可复现参考配方；熟萝卜叶每100g营养为AI粗估，默认沥水、未加油，**不是USDA萝卜叶条目**。两者均可编辑，不能当作实际餐馆/家庭做法。用户原句可本地解析为400g米饭、300g参考炒牛肉、80g熟萝卜叶，后两项附AI估算说明。原有历史记录继续保留保存时的营养快照，实时AI的结果也不会被这两条预估条目强行覆盖。

运行 `python scripts/build-ai-portion-library.py` 可从审核过的预估表复现JSON；原USDA生成脚本仅更新原35项和115项食物，不覆盖AI扩展文件。营养屋的“小包的食物库与估算说明 → 查看拳头份量库”可查看全部97项和出处类别。
