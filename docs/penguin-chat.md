# 企鹅小家

全局聊天按钮打开独立聊天页面，不新增底部 Tab。记账、营养、冰箱、旅行页面分别默认鲍比、小包、嘟嘟糕、黏黏包，个人页面默认家族群聊。可切换单聊/群聊、新建/继续/删除对话；切换模式保留旧对话在聊天记录中。

## 角色和群聊

服务端 `server/chat.mjs` 固定世界观、四只企鹅人格和关系。鲍比憨厚真诚但不愚笨，小包聪明毒舌但不恶意攻击，嘟嘟糕软萌偶尔使坏，黏黏包乖巧并缓慢学会玩笑。彪彪负责个人页，不作为固定家庭成员加入聊天。普通回复每只通常 1–3 句话，严肃问题认真回答。

一轮一次 OpenAI Responses 请求（默认 gpt-4.1-mini、store:false），输出 1–4 个不同角色气泡和最多 3 张提议卡片。单聊只允许所选角色；`@角色` 只允许被点名者。客户端和后端检查角色、重复回复、操作参数；单聊欢迎页只显示所选企鹅头像，群聊显示四只。模型仍可能出现不自然对白，需要真实服务持续调优，不保证事实正确。

## 保存、确认和隐私

Dexie v7 新增独立 chatThreads、chatMessages、chatMemories、chatGrowth，原表及数据库名称不变。

- 消息本地保存，包括未确认卡片，失败后可重试原消息，停止等待或关闭会中止请求。
- 按用户设置，点击发送即同意上传本次文字、最多 32 条近期对话（按文字大小进一步截断）、最多 20 条相关/近期已确认记忆、成长程度和当天日期。不发送账单、照片、库存、身体资料、全部历史或 API 密钥。
- 记忆分偏好、真实经历、家庭小剧场。后者不能作为真实用户经历。新增记忆须确认；个人页可手动添加、查看、修改、删除。
- 账单、食材、购物清单、饮食是建议卡片，可以先修改，确认后才写对应业务表。事务读取最新待确认状态防止双击；业务记录用卡片编号派生唯一 ID，旧待确认卡片的重复导入也不能生成第二笔同编号记录。取消不保存业务数据。
- 不支持通过聊天修改/删除既有业务记录。用户直接删除对话不会删除已经确认的记忆或业务记录。
- 使用共享个人页连接设置。访问口令仅 sessionStorage；API 密钥仅 Worker Secret。

## 黏黏包的成长

初始 0/100，不根据随机数成长。AI 提议具体互动依据，经用户确认后每次 +1，至少间隔一天、任意连续 7 天最多两次。成长依据与状态独立持久化；0–20 以乖巧为主，21–50 偶尔主动玩笑，51–100 更机灵但保留温和乖巧。个人页可调整数值、删除依据（减一级）、重置。删除普通聊天不重置成长。

## 备份和离线

原 version:1 格式增加可选 chat 部分，保存对话、消息/卡片状态、独立记忆和成长依据。完整校验后与其他数据同一事务合并，旧备份没有 chat 不清除聊天资料。相同 ID 更新，其他记录保留；包含 chat 时成长状态按备份恢复。API 连接和口令不导出。无照片备份也包含聊天。

离线可以打开已缓存页面、翻看聊天和管理本地记忆；OpenAI 对话需要联网和可用 Worker。

## 后端启用与验证

现有手动 `Deploy Xiaobao AI backend` 工作流部署新增 `/chat`，需要 GitHub Actions Secrets：CLOUDFLARE_API_TOKEN、CLOUDFLARE_ACCOUNT_ID、NUTRITION_API_KEY、NUTRITION_ACCESS_CODE。随后在个人页填 Worker 根地址和访问口令。已有旧 Worker 也需要重新部署才会有 `/chat`。

工作流验证营养、食谱、游记和单聊，共 4 次小额真实 OpenAI 调用。它不会随前端 Pages 推送自动运行。共享默认额度为每日 30、每分钟 5 次，所有 AI 功能共同使用，可在 Wrangler 配置调整。

自动测试使用假密钥与模拟提供者；浏览器模拟回复仅验证流程，不能证明真实模型语气或真实 API 连接成功。不要在聊天中粘贴密钥。

## 操作反馈

生成对白中的“记好了/已经保存”等未获本地确认的成功说法会被服务端和客户端改成待确认提示；已有旧对白也在显示时纠正，不自动补写账单。卡片是操作状态的依据。确认账单后显示实际保存的日期、分类和金额，“查看账单”会切换到账单明细和该账单月份，避免当前月份或分类统计隐藏了记录。手动后端工作流也验证真实 OpenAI 能为明确的午饭35元请求生成账单卡片，验证不写入任何用户账单。

## 聊天中的饮食和冰箱

聊天取消 AI 同意勾选框，保留发送即同意的文字提示；输入和切换模式不会自动调用。所有业务写入仍需确认卡片。饮食卡片可设置日期、餐次、食物及克重，展开修改每100克热量、蛋白质、碳水和脂肪，显示本餐合计和估算假设。事务保存到现有 meals 表，source 为 ai（手动修改营养数值时为 manual）、photo/expenseId 为 null，进入营养屋后由本地原有目标逻辑计算达标情况；不会自动重复生成账单或扣减库存。对应 mealType/foods 字段在旧非饮食卡片中可省略，旧备份仍兼容。

确认后可以打开相应日期的营养屋、冰箱或购物清单。单聊同样可以请求各种记录，但仅所选企鹅回应。真实部署验证一次聊天能返回账单、饮食和冰箱三张卡片，验证不写入用户记录。

## 续聊、草稿与记录一致性

再次打开恢复上次选择的对话与企鹅。切换企鹅会继续该角色最近的对话，“新聊天”才创建新页。输入草稿在本机IndexedDB延迟保存，关闭时立即保存；发送成功写入用户消息后清除草稿；中断的消息恢复后提供重试。草稿随完整备份保存，旧备份未提供草稿时不清除本机草稿。UI会话指针和AI口令不随备份导出。

账单、食材、购物备注统一最大500字符，食材名称100字符、单位20字符；实际确认写入复用业务表校验，避免聊天接受但备份拒绝。历史合法长备注可直接恢复，无需截断。已知食物首先采用营养屋同一字典的每100克营养，AI只估算份量和识别，未知菜品保留明确的AI估算；用户仍可修改数值。

个人页提供本应用记录/照片编码大小估算、站点空间配额、上次导出时间。超过7天未导出或已有记录但未导出会显示提醒。可主动申请浏览器持久存储；它不等于云同步，也不能防止用户手动清除数据。

未发送的新对话草稿会在聊天记录中提供独立入口；切回企鹅时优先恢复更新的草稿，开始新聊天前会提醒是否清空尚未发送的草稿。
