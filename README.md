# 天天爱记 · TT_aiji_pwa

使用 React、TypeScript、Vite、Dexie 构建的个人记账、营养记录、食材管理与旅行记录 PWA。人民币金额以整数分保存，账单、预算、饮食照片、营养资料、冰箱库存与购物清单保存在当前浏览器的 IndexedDB 中。本地功能无需账号和后端；照片或文字 AI 分析需单独配置服务端。

## 开发

需要 Node.js 22.12+（当前环境使用 Node.js 24）。

```sh
npm ci
npm run dev
```

## 验证与构建

```sh
npm test
npm run build
npm run preview
```

界面采用企鹅游乐园主题：原创毛绒企鹅插画、奶油黄门票式月度统计、蜜桃色记账按钮和冰蓝底部导航。账单、小包的营养屋、嘟嘟糕的嘟嘟冰箱、黏黏包的旅行册、个人有独立页面；账单页面内提供“账单明细／分类统计”切换，共用所选月份、开销和预算；新增和编辑使用支持键盘焦点与 Escape 关闭的弹窗。插画随 PWA 一起离线缓存。

支持新增、编辑、删除账单，按月统计和分类汇总，JSON 备份导入导出。账单页面的“分类统计”以可点击饼图展示各分类占比，也可点击分类列表查看所选月份的逐笔明细。明细按日期从新到旧排列，包含金额、日期和备注，并支持编辑与删除；切换月份会同步更新饼图和明细。导入合并账单，相同编号更新已有记录，导入前验证所有数据并确认。单笔金额范围为 0.01–1,000,000 元。

生产构建自动生成 manifest 和 service worker；首次联网访问后可离线打开。开发模式不注册离线缓存，验证 PWA 请使用生产预览。部署 dist 到支持 HTTPS 的静态托管平台，站点路径默认是域名根目录。支持的浏览器可通过菜单安装；iOS Safari 可选择“分享 → 添加到主屏幕”。

数据仅保存在当前浏览器，不会跨设备同步。清理网站数据、卸载相关浏览器或使用隐私模式可能导致数据丢失，请定期导出备份。备份包含账单明文，请妥善保管。

## 记账分类

按顺序提供：餐饮、食品日用、生活缴费、交通、购物、娱乐、医疗、旅行、人情、其他。旧账单中的“住房”会自动归入“生活缴费”，金额、日期、备注与编号保持不变；旧备份导入时也会进行相同转换。

## 每月预算

在“本月开销”旁选择“设置预算”，为当前所选月份设置预算。预算按月独立保存，允许零预算；可以修改或取消。卡片会随账单变化显示“还能花”“预算已用完”或“已超支”，金额以整数分计算。预算保存在同一浏览器的 IndexedDB 中，刷新或离线仍可用。

导出备份包含账单和全部月度预算。导入时按账单编号与预算月份合并；旧版仅有账单的备份不会清除现有预算。导入前校验所有账单和预算，事务写入，避免损坏备份造成部分导入。

## 小包的营养屋

底部“营养屋”是独立 Tab，配有更活泼的原创小包插画。支持早餐、午餐、晚餐、加餐，照片本地压缩保存，并可通过文字或食物库记录多种食物。

- **小包自己算**：115项本地食物与参考中餐配方，支持“米饭150克、鸡胸肉100克、一个鸡蛋”等文字，完全离线，无 API 费用。未匹配内容必须补充、选择食物或明确忽略，不能静默丢弃。
- **小包帮你问问AI**：照片或文字只在主动点击且勾选同意后发送。返回的食物、份量和营养需要确认，可手动修改。个人页统一管理 AI 连接，只填写后端地址与访问口令，OpenAI 密钥在服务端。
- **每日目标**：成年人填写身高、体重、年龄、公式性别参数、活动量及减脂/维持/增重目标，生成可修改的热量、蛋白质、碳水与脂肪范围，也可直接手动设置。建议为通用估算起点，不是医疗食谱。
- **饮食统计**：每日摄入与目标范围，低于/范围内/超出；七日趋势和平均值仅使用有记录的日期，空白日期不计为零摄入。历史按当前目标对照。
- **可选关联记账**：确认饮食时可选填开销，事务生成餐饮账单。编辑关联费用复用原账单编号，修改份量不重复记账；删除饮食可选择保留或同时删除账单。在账单页删除关联账单会取消关联，保留饮食记录。
- **备份**：完整导出包含营养快照、照片和身体/目标资料，不包含 AI 访问口令。照片较多时可选择无照片备份；导入无照片备份会保留本机已有同编号记录的照片，不能在新设备恢复省略的照片。单个备份导入限制50MB，导出超过限制会提示改用无照片备份。旧版账单备份不会清空饮食或目标；损坏记录或缺失关联账单会整笔回滚导入。

食物来源与目标算法详见 [docs/food-data.md](docs/food-data.md)，源数据校验与生成脚本为 `scripts/build-food-library.py`。

AI 后端代码、Secret 配置及部署说明见 [docs/nutrition-ai.md](docs/nutrition-ai.md)。前端推送仍自动发布到 GitHub Pages；AI 后端有独立、需手动运行的 **Deploy Xiaobao AI backend** 工作流。

当前服务是否可用取决于实际后端地址与有效 API 凭据。单元测试中的 AI 响应是固定测试数据，不能视作真实 GPT 调用验证。

## 嘟嘟糕的嘟嘟冰箱

底部“嘟嘟冰箱”是独立 Tab，角色 Dudu Gao 配有与鲍比、小包同系列的原创毛绒布丁帽企鹅插画。提供“我的冰箱／今天吃什么／购物清单”，无语音功能。

- 手动简单添加，名称必填；数量、单位、到期日期与备注可选，支持冷藏、冷冻、常温。数量可写“半袋”“一些”，不强制克数。可编辑、标记用完或丢弃。
- 到期日期按本地日期提醒，今天／三天内优先展示；已过日期的库存不参与推荐。未填日期不表示安全或不安全。
- **嘟嘟糕推荐菜**：20道本地家常食谱，按人数缩放配方，可设置时间、忌口／过敏及饮食偏好。按名称别名匹配，区分生米和熟饭、生肉和熟肉；只在同单位或明确重量/容量换算后判断够用。不同包装/个数与克数不自动猜测换算，显示“份量待核对”。
- 推荐区分“现在就能做／补几样就能做／份量待核对”；同等缺料数与待核对数时优先使用快到期食材。基础调料按可编辑的常备清单处理。
- 输入想吃的菜，查看所需配方与库存差额。缺料加入购物清单，模糊库存产生待核对项；同一道菜同种未入库食材不重复添加。清单可手动新增、修改、勾选、移除。
- 勾选买到后确认实际数量、位置和日期，再作为新库存批次放入；可选以总金额生成一笔“食品日用”账单。事务写入并检查购物项状态，防止重复入库和部分记账。
- 做菜后确认剩余数量或用完，默认保留现有记录；不自动扣除推测用量。可选生成个人饮食记录，填写个人食用份数；按配方估算，不把整锅算作一人摄入。营养不全的菜需在营养屋补充后记录。
- **嘟嘟糕问AI**：复用小包的安全 Worker 及访问口令，新 `/recipes` 接口只在明确同意并点击后发送食材名称/数量、菜名和推荐设置。服务端及前端再次筛除命中的忌口；模型响应仍须人工核对。不传身体资料、账单或库存照片。二者共用每日／每分钟额度。
- 可勾选四项营养估算；本地菜按现有食材库与配方重量计算，AI未知食材可使用有边界校验的估计值，缺少数据时明确显示小计，不能当作整餐营养。
- 完整备份包含库存、购物清单和冰箱偏好。按编号合并，偏好按备份恢复；旧备份没有冰箱字段则保留本机资料。导入前验证冰箱数据，失败不会部分写入财务数据。API访问口令不导出。

纯本地库存/菜谱/购物流程支持离线；AI需安全配置并部署更新后的 Worker，详情见 [docs/nutrition-ai.md](docs/nutrition-ai.md)。

## 个人 · 彪彪数据中心

底部“个人”由原创毛绒海鸥彪彪（Biao Biao）负责，使用与鲍比、小包、嘟嘟糕一致的插画风格。集中提供 AI 连接和原有数据备份。小包与嘟嘟糕的设置入口跳转到个人页，不再分别维护设置表单。

服务根地址保存在 IndexedDB 原有 settings 表，会复用已有配置；访问口令持久保存在当前设备的 localStorage，不随备份导出。保存设置不调用 AI，也不代表服务已验证。OpenAI API 密钥继续通过 GitHub Actions Secrets 安全配置到后端，个人页提供配置说明与安全页面链接，不能在公开 PWA 输入或保存服务端密钥。未配置时，餐食弹窗显示提示并保留已输入内容，可以继续本地计算。

## 黏黏包的旅行册

独立“旅行册”Tab 使用原创毛绒旅行伙伴黏黏包。全国地图点击省份后，在**同一个地图区域**切换省内城市，返回全国即可回到上一层。城市弹窗显示景点列表、手动去过标记和关联旅程。

支持多城市起止日期、景点、感受、12张本地压缩照片、可编辑游记；完成日期已到的旅行自动点亮，独立手动标记不会随旅行删除。地图、省内城市列表和本地整理故事模板离线可用；照片与资料纳入个人页备份，旧备份不清除旅行记录。

接入373条带来源和日期的5A名录快照。**4A全量名录仍待接入**，城市4A入口明确说明覆盖不完整，自填评级单独标记，不伪装为官方名录。行政区特殊地区、许可、更新日期和生成步骤见 [docs/travel-data.md](docs/travel-data.md)。

“黏黏包问AI写游记”复用个人页连接，需要部署支持 `/travel-story` 的新版后端；只上传本次旅行文字，照片默认不发送，AI结果必须核对确认。后端未配置时可继续本地记录和整理。

### 企鹅小家图片聊天

聊天输入区支持每条消息附一张 JPG、PNG 或 WebP 图片（原文件不超过10MB）。复用本地照片压缩，最长边960像素；选择后可移除，点击发送才会交给 OpenAI。可仅发图片或配文字，发送失败可重试同一条消息。每轮只上传当前消息的图片，历史图片留在本机，以文字标记说明本轮未上传。未发送图片在切换聊天或关闭窗口后不保留，文字草稿不受影响。

图片随聊天记录保存在 IndexedDB，可点开查看，并计入个人页空间统计；照片备份开关同时控制聊天、饮食和旅行照片。无照片备份恢复时保留本机同编号聊天记录已有的图片。图片内容不能直接触发业务写入，仍须用户明确要求并确认卡片。需要部署新版 `/chat` Worker；部署检查使用生成的红色色块验证真实 OpenAI 视觉输入，不发送用户图片。

### 分别配置聊天与工具模型

Worker 的 `server/wrangler.toml` 中，`CHAT_MODEL` 默认为 `gpt-5-mini`，仅用于企鹅小家的文字和图片聊天；`NUTRITION_MODEL` 默认为 `gpt-4.1-mini`，用于饮食、食谱和游记。聊天采用 minimal 推理以控制等待时间，保留严格结构化输出与业务确认卡片。`/health` 的 `chatModel` 和 `model` 分别报告两类模型。修改模型后需重新部署 Worker，前端连接地址、访问口令和本地数据均无需更换。部署前先检查账号能否调用升级模型并完成看图和 JSON 输出，检查失败不会替换当前 Worker。

本地饮食文字支持“拳／拳头／个拳头”（如“米饭两拳＋鸡胸肉半拳”）：35项有同种食品杯重依据的食物使用1拳≈1杯体积粗估，显示估计克数和假设，可手动修改。参考依据、适用限制及可复现数据见 [拳头份量说明](docs/hand-portions.md)；不对未知菜品统一套用重量。

拳头参考库现含97项：35项USDA杯重参考及62项单独标为低置信度的AI预估（包含粗略范围和做法假设）。新增AI参考炒牛肉配方与熟萝卜叶营养条目，可本地识别“米饭400g+炒牛肉两拳+萝卜叶半拳”。食物库来源说明内可查看整库；预估文件不会实时调用API，也不会改写历史餐食或覆盖实时AI对新增估算条目的营养结果。

### 我的食物库

营养屋的AI分析、手动食物和已保存餐食均可在核对后逐项勾选“同时加入我的食物库”，随保存餐食一起写入。可确认名称/别名、每100克营养、默认克数、可选的一拳克数及做法用油说明；整餐重量不会自动当成一拳。同名条目明确更新，不同做法请使用不同名称；重名别名冲突会阻止保存，餐食与入库在同一事务中完成。

本地计算优先匹配个人名称与别名。营养屋“我的食物库”支持搜索、修改、删除，修改不会改变旧餐食快照。数据在Dexie v10的独立 `personalFoods` 表，纳入空间统计及备份；旧备份缺少该字段时保留现有个人食物，合并导入发生名称/别名冲突会整笔回滚。个人条目不自动上传或加入聊天上下文，不替代实时AI对当前描述的分析。

### 按模块导出备份

个人页“数据备份 → 导出范围”可选择全部、账单、营养屋、嘟嘟冰箱、旅行册、企鹅小家或个人。账单包括预算；营养屋包括目标和我的食物库；旅行包括国内与海外；个人只包括企鹅已确认记忆和成长，不含对话、API地址和访问口令。带照片的模块可选择不包含照片，生成的JSON可使用原导入入口。

单模块备份只读取对应表，`exportScope` 标记范围，导入时检查范围与字段是否匹配，不修改缺席的模块。营养屋独立备份不附带任何账单并省略账单关联；新设备恢复后可以重新关联，在原设备导入保留已有有效关联。全量备份继续保留关联账单及链接。无照片恢复保留本机已有同编号照片。

只有“全部数据”导出更新上次完整备份时间；单模块导出单独记在本机元信息，不会让完整备份提醒误以为所有记录都已备份。历史备份不需要包含 `exportScope`，仍可导入。
